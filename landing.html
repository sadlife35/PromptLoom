How it works

Hold F8. A small overlay appears with a live level meter so you know we are listening. Speak clearly for one to twenty seconds. Release. whisper.cpp transcribes locally in about a second. The text is corrected against your project vocabulary — a plain .promptloom/terms.yml you edit yourself — and pasted into whatever window had focus when you started. Alt-tabbed away? We copy to clipboard instead. Pressed Esc? We discard the audio and do nothing.

What this is, honestly

One developer's project. Windows 10/11 x64 only. The installer is unsigned, so Windows will warn. The UI stalls for a second or two during transcription. There is no auto-updater and no telemetry — if the model stops working, you fix it by hand. If you need a polished product today, use Wispr Flow or Windows's built-in dictation. If you want the thing you can read, audit, modify, and run offline forever, you are in the right place.

Questions

Is my audio sent anywhere?

No. After the model is installed, zero network calls are made. The Settings window has a privacy audit button that scans the scratch directory to verify nothing persists.

What speech model does it use?

whisper.cpp with the ggml-base.en weights (about 148 MB). The model file is SHA-256 verified at download, and again at any time via Settings → Verify.

Why Windows only?

It is where I use it. macOS and Linux ports are planned — contributions welcome on GitHub.

Why not whisper-rs or a Python wrapper?

Tried whisper-rs. Hit libclang, MSVC, and bindgen trouble for the better part of a day. The build spec explicitly permits a managed sidecar, so PromptLoom shells out to the official prebuilt whisper-cli — zero compile fragility for anyone building from source.

Is this ready for production?

No. This is an alpha. Use it to replace Windows's built-in dictation for coding, email, and comments. Do not rely on it to transcribe anything legally or clinically significant.
